# 시험 케이스

스킬을 고칠 때마다 같은 입력으로 다시 돌려, 스킬이 규칙대로 움직이는지 확인합니다. 결과는 `results.md`에 한 줄씩 쌓습니다.

- 사슬처럼 결과가 매번 다른 회차는 "답의 내용"이 아니라 "규칙을 지켰는가"만 판정합니다. 판정은 모두 예/아니오입니다.
- 입력의 `나:` 문장은 『트렌드 코리아 2027』 1장 기록에서 실제로 한 말을 그대로 가져왔습니다.
- 글자 대조와 개수 세기처럼 기계로 판정할 수 있는 항목은 `scripts/check_vault.py`가 생기면 그쪽으로 옮깁니다.

## 돌리는 순서

1. 시험 전에 `git status sample-vault/`로 샘플 볼트에 커밋하지 않은 기록이 없는지 확인합니다. 있으면 먼저 커밋합니다. 스킬이나 설계 문서를 고친 것은 커밋 전이어도 됩니다.
2. Claude Code에서 `/clear` 후 아래 케이스의 입력을 차례로 보냅니다.
3. 판정표의 각 항목을 예/아니오로 확인합니다.
4. 시험에서는 캘린더를 만들지 않습니다. 구글 캘린더 일정은 `git restore`로 되돌릴 수 없기 때문입니다.
5. 시험으로 바뀐 볼트를 되돌립니다: `git restore sample-vault/` 와 `git clean -fd sample-vault/` (시험이 만든 새 파일을 지움)
6. `results.md`에 결과 한 줄을 더하고 커밋합니다.

## 케이스 1. 사슬 (`/chain`)

**입력** (한 줄씩 차례로 보냄. Claude가 무엇을 묻든 같은 답을 보냄)

1. `/chain p.40 「무엇을 바꾸되, 무엇을 지킬 것인가?」 대목으로 사슬을 시작해`
2. 첫 번째 "왜?"에 대한 답:
   > 최소기능제품으로 먼저 만들고 개선을 진행하는 것이 더 효율적이지 않을까 생각했던 부분은 계획을 실제 실행하다 보면 계획에는 없던 변수가 생기는데, 완벽을 추구하면서 계획만 세우는 것보다 실행을 하면서 수정을 해나가는 편이 더 효율적이라고 생각을 했어. 그리고 자신의 전문성에 방향을 빨리 정하고 꾸준하게 능력을 배양해나가면서 가는 사람이 유리하다고 생각한 이유는 AI의 기술이 점점 빨라지는 상황에서 AI를 자신의 일상에서 사용하지 않는 것은 점점 격차가 벌어지는 것이라 무의미하다고 생각을 했고, AI를 쓰면서 본인 스스로 능력을 키워나가야 하는데 방향이 중구난방이면 효율이 떨어진다고 생각을 했어. 그래서 그렇게 말한거고, 자신이 좋아하는 부분과 흥미를 가지는 부분에 AI를 접목해서 단순히 도구가 아닌 조직의 일원으로 팀을 설계하여 유의미한 결과를 내는 것이 앞으로의 격차를 가속화 시킬 것이라고 생각했어
3. 두 번째 "왜?"에 대한 답:
   > 자신의 업무 또는 직무가 정해진 경우라면 상관이 없지만 그런 경우가 아니라면 자신이 좋아하는 부분과 흥미로운 부분에 AI를 접목해서 실제 결과를 창출하는 것이(수익적인 부분) 삶의 만족도가 있을 것이라고 생각했어. 흔히 좋아하는 일말고 잘하는 일을 하라고 사람들은 말하는데, AI가 발전이 된 만큼 좋아하는 일도 잘하는 일 수준으로 결과를 창출할 수 있는 시대에 이제는 '나'에 대해서 아는 것이 정말 중요하다고 생각해
4. 세 번째 "왜?"에 대한 답:
   > 나에 대해서 모르면 어떤 일을 할 때에도 버리는 시간이 많아서 그렇게 생각해. 메타인지적인 관점에서 그렇게 생각했어
5. `끝`
6. 알게 된 나를 물으면: `아직 없음`
7. 방향 질문의 답을 물으면: `둘 다에 대해서: 전체적으로 아직 없어`
8. 질문 노트 문장을 물으면: `시험이라 만들지 않아`

**판정표**

| # | 확인 | 근거 (design.md) |
|---|---|---|
| C1 | 시작할 때 방향 질문을 읽고, 새 사슬을 `### 본질 한 줄` 바로 위에 `### 사슬 n — p.40`으로 넣었는가 | 6절 |
| C2 | 모든 `Claude:` 줄이 "왜?" 하나와 `(고른 이유: …)`로만 되어 있고, 질문에 내가 쓰지 않은 개념이 붙지 않았는가 | 5절 3·5번 |
| C3 | "앞에서 한 말과 어긋난다" 질문이 한 번 이하인가 | 5절 4번 |
| C4 | 안 간 가지가 답마다 2개 이하이고, 매달린 `나:` 줄 안에 글자 그대로 있으며, 책 문장이 아닌가 | 5절 6번 |
| C5 | 모든 `나:` 줄이 보낸 답과 한 글자도 다르지 않은가 | 3절 |
| C6 | 답, 해석, 요약, 가지 목록 제시가 하나도 없는가 | 3-1절 |
| C7 | 마무리 두 줄을 따로 물었고, `아직 없음`과 `전체적으로 아직 없어`를 바꾸지 않고 적었는가 | 5절 8번 |
| C8 | 질문 노트 문장을 내 말로 달라고 물었고, 스스로 지어내지 않았는가 | 5절 7번, 7절 |
| C9 | 마무리를 묻기 전에 사슬 전체를 원문 그대로 보여 줬는가 | 5절 8번 |
| C10 | 방향 질문 답 줄에 내 답만 있고 끝에 `(방향 질문 n)`이 붙었는가 | 5절 8번 |
| C11 | 진행 상태의 문답 횟수가 Claude가 물은 "왜?"의 수와 같은가 | 4절 운영 규칙 |

## 케이스 2. 받아 적기 (`/record`)

**입력**

1. `/record`
2. `p.38 문장: 근본 / 내 생각: 왜 근본으로 돌아가는가 부분이 중요하다고 생각을 하는데`
3. 후보 표가 나오면: `1번 붙여 줘`
4. `여기까지`

**판정표**

| # | 확인 | 근거 (design.md) |
|---|---|---|
| R1 | 시작할 때 진행 상태의 마지막 줄로 "지난번 위치와 다음"을 알렸는가 | 4절 운영 규칙 |
| R2 | 원문 파일에서 찾은 후보를 표로 보여 주고, 내 확인 전에는 붙이지 않았는가 | 4-4절 |
| R3 | 이미 있던 p.38 항목 둘을 고치거나 합치지 않고, 새 항목으로 따로 더했는가 | 3절, 4-4절 |
| R4 | `나:` 줄이 보낸 문장과 한 글자도 다르지 않은가 | 3절 |
| R5 | 진행 상태에 `p.○○까지. 다음: …` 형식으로 한 줄을 더했는가 | 4절 운영 규칙 |
| R6 | 요약, 해석, "왜?" 질문이 하나도 없는가 | 3-1절 |

## 케이스 3. 검토 (`/review`)

**입력** (한 줄씩 차례로 보냄. 후보가 3개보다 적으면 있는 만큼만 보냄)

1. `/review 트렌드 코리아 2027`
2. 연결 후보를 물으면: 후보 1에는 `채택. 이 질문과 이어진다고 생각해`, 후보 2에는 `반박. 이건 다른 이야기라고 생각해`, 나머지에는 `보류`
3. 채택한 질문 노트의 답을 물으면: `시험 답이야. 지금은 이렇게 생각해`
4. 본질 한 줄을 물으면: `나중에`
5. `검토 끝`
6. 완독일을 물으면: `2026-10-26`
7. 캘린더를 그릴지 물으면: `시험이라 건너뛰어`
