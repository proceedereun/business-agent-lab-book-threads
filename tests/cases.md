# 시험 케이스

스킬을 고칠 때마다 같은 입력으로 다시 돌려, 스킬이 규칙대로 움직이는지 확인합니다. 결과는 `results.md`에 한 줄씩 쌓습니다.

- 사슬처럼 결과가 매번 다른 회차는 "답의 내용"이 아니라 "규칙을 지켰는가"만 판정합니다. 판정은 모두 예/아니오입니다.
- 입력의 `나:` 문장은 실제 기록과 겹치지 않도록 "시험"이 들어간 문장을 씁니다. 실제 기록과 같은 문장을 넣으면 Claude가 중복을 먼저 묻게 되어 시험하려던 동작을 볼 수 없습니다(4.15판에서 바꿈. 그 전 케이스 1은 1장 실제 기록의 문장을 썼음).
- 글자 대조와 개수 세기처럼 기계로 판정할 수 있는 항목은 `scripts/check_vault.py`로 옮깁니다(사슬 마무리·캔버스는 옮김).

## 돌리는 순서

1. 시험 전에 `git status sample-vault/`로 샘플 볼트에 커밋하지 않은 기록이 없는지 확인합니다. 있으면 먼저 커밋합니다. 스킬이나 설계 문서를 고친 것은 커밋 전이어도 됩니다.
2. Claude Code에서 `/clear` 후 아래 케이스의 입력을 차례로 보냅니다.
3. 판정표의 각 항목을 예/아니오로 확인합니다.
4. 시험에서는 캘린더를 만들지 않습니다. 구글 캘린더 일정은 `git restore`로 되돌릴 수 없기 때문입니다.
5. 시험으로 바뀐 볼트를 되돌립니다: `git restore sample-vault/` 와 `git clean -fd sample-vault/` (시험이 만든 새 파일을 지움)
6. `results.md`에 결과 한 줄을 더하고 커밋합니다.

## 케이스 1. 사슬 (`/chain`)

**입력** (한 줄씩 차례로 보냄. Claude가 무엇을 묻든 같은 답을 보냄)

입력은 번호를 빼고 문장만 보낸다.

1. `/chain p.40 「무엇을 바꾸되, 무엇을 지킬 것인가?」 대목으로 사슬을 시작해`
2. 첫 번째 "왜?"에 대한 답:
   > 시험 답: 계획보다 실행이 먼저라고 생각했고, 실행하다 보면 생각지 못한 변수가 생기니까 고쳐 가면서 가는 게 낫다고 봤어. 그래도 방향이 흩어지면 힘이 빠진다고 생각해
3. 두 번째 "왜?"에 대한 답:
   > 시험 답: 방향이 흩어지면 같은 시간을 써도 남는 게 적어서 그렇게 생각해. 그리고 좋아하는 일이어야 오래 버틸 수 있다고 봤어
4. 세 번째 "왜?"에 대한 답:
   > 시험 답: 오래 버티는 힘은 결국 내가 왜 하는지 알 때 생긴다고 생각해
5. `끝`
6. 알게 된 나를 물으면: `아직 없음`
7. 방향 질문의 답을 물으면: `둘 다에 대해서: 전체적으로 아직 없어`
8. 질문 노트 문장을 물으면: `시험이라 만들지 않아`

**판정표**

| # | 확인 | 근거 (design.md) |
|---|---|---|
| C1 | 시작할 때 방향 질문을 읽고, 새 사슬을 `### 본질 한 줄` 바로 위에 `### 사슬 n — p.40`으로 넣었는가 | 6절 |
| C2 | 모든 `Claude:` 줄이 "왜?" 하나와 `(고른 이유: …)`로만 되어 있고, 질문에 내가 쓰지 않은 개념이 붙지 않았는가 | 5절 3·5번 |
| C3 | "앞에서 한 말과 어긋난다" 질문이 한 번 이하인가 | 5절 4번 |
| C4 | 안 간 가지가 답마다 2개 이하이고, 매달린 `나:` 줄 안에 글자 그대로 있으며, 책 문장이 아닌가 | 5절 6번 |
| C5 | 모든 `나:` 줄이 보낸 답과 한 글자도 다르지 않은가 | 3절 |
| C6 | 답, 해석, 요약, 가지 목록 제시가 하나도 없는가 | 3-1절 |
| C7 | 마무리 두 줄을 따로 물었고, `아직 없음`과 `전체적으로 아직 없어`를 바꾸지 않고 적었는가 | 5절 8번 |
| C8 | 질문 노트 문장을 내 말로 달라고 물었고, 스스로 지어내지 않았는가 | 5절 7번, 7절 |
| C9 | 마무리를 묻기 전에 사슬 전체를 원문 그대로 보여 줬는가 | 5절 8번 |
| C10 | 방향 질문 답 줄에 내 답만 있고 끝에 `(방향 질문 n)`이 붙었는가 | 5절 8번 |
| C11 | 진행 상태의 문답 횟수가 Claude가 물은 "왜?"의 수와 같은가 | 4절 운영 규칙 |
| C12 | 마무리 두 줄이 사슬의 맨 끝(가장 바깥 안 간 가지 다음)에 들여쓰기 없이 있는가. `check_vault`의 "사슬 마무리" 항목과 같은 것을 눈으로 확인 | 6절 |

## 케이스 3. 검토 (`/review`)

**시험 준비** (책 노트에 이미 실제 검토가 끝나 있어, 검토 전 모양으로 잠시 되돌린 뒤 시작합니다)

- Claude Code에 이렇게 보냅니다: `시험 준비: 『트렌드 코리아 2027』 책 노트에서 ### 본질 한 줄, ## 2~## 5 아래 내용을 비우고, finished와 calendar_events, 진행 상태의 "검토 끝" 줄도 비워 줘. 다른 줄과 질문 노트는 건드리지 마. 커밋하지 마.`
- 준비로 지운 줄 때문에 시험 중 `check_vault`의 "내 말" 항목이 실패할 수 있습니다. 판정에는 넣지 않습니다.
- 시험이 끝나면 5번대로 `git restore`로 되돌립니다. 실제 검토 기록이 그대로 돌아옵니다.

**입력** (한 줄씩 차례로 보냄. 후보가 3개보다 적으면 있는 만큼만 보냄)

1. `/review 트렌드 코리아 2027`
2. 연결 후보를 물으면: 후보 1에는 `채택. 이 질문과 이어진다고 생각해`, 후보 2에는 `반박. 이건 다른 이야기라고 생각해`, 나머지에는 `보류`
3. 채택한 질문 노트의 답을 물으면: `시험 답이야. 지금은 이렇게 생각해`
4. 본질 한 줄을 물으면: `나중에`
5. `검토 끝`
6. 완독일을 물으면: `2026-10-26`
7. 캘린더를 그릴지 물으면: `시험이라 건너뛰어`

**판정표**

| # | 확인 | 근거 (design.md) |
|---|---|---|
| V1 | `## 1. 내 구역`이 마지막 커밋과 비교해 `### 본질 한 줄`에 새로 적은 내 말 외에는 한 글자도 다르지 않은가 | 3절, 6절 |
| V2 | `## 2`·`## 3`의 문장마다 근거(쪽, 사슬 번호, 노트 이름)가 붙어 있는가 | 3-1절, 8절 |
| V3 | 연결 후보가 3개 이하이고, 후보마다 이유가 한 문장인가 | 4절 운영 규칙, 8절 |
| V4 | `## 4. 내 검토`의 `나:` 줄이 보낸 말과 한 글자도 다르지 않은가 | 3절 |
| V5 | 채택한 후보만 `## 5. 링크`에 `[[링크]]`로 갔고, 반박·보류한 후보는 링크가 아닌가 | 6절 |
| V6 | 질문 노트의 답이 덮어쓰이지 않고 `## 답의 이력` 아래 `### 날짜` 제목으로 쌓였는가. 채택한 후보가 질문 노트가 아니어서 답을 묻지 않았으면 "해당 없음" | 7절 |
| V7 | 캘린더를 건너뛰라는 말을 따라 일정을 만들지 않았는가 | 4-2절 |

## 케이스 4. 캔버스 (`draw_canvas.py`)

**입력** (터미널에서 차례로 실행)

1. `sha256sum sample-vault/20_reading/books/*.md` (책 노트 기록)
2. `python3 scripts/draw_canvas.py` 를 두 번 돌리고, 돌릴 때마다 `sha256sum sample-vault/20_reading/books/*.canvas`
3. `python3 scripts/check_vault.py`
4. 『대한민국 부의 감각』 캔버스에서 카드 글 한 글자를 스크립트로 바꿈 (예: `나: 생존을 해야 하니까` → `나: 생존을 해야 하니깐`) 후 `python3 scripts/check_vault.py`
5. `python3 scripts/draw_canvas.py "대한민국 부의 감각"` 후 `python3 scripts/check_vault.py`와 `sha256sum`
6. 옵시디언에서 두 캔버스를 열어 봄

**판정표**

| # | 확인 | 근거 (design.md) |
|---|---|---|
| D1 | 두 책의 캔버스가 책 노트 옆에 생기고, `check_vault` 14개가 모두 통과하는가 | 6-1절, 11절 |
| D2 | 두 번 돌린 캔버스의 sha256이 같은가 | 6-1절 캔버스 규칙 2 |
| D3 | 돌리기 전과 뒤의 책 노트 sha256이 같고, `git status`에 `.canvas` 말고 바뀐 것이 없는가 | 6-1절 캔버스 규칙 1 |
| D4 | 카드 글을 한 글자 바꾸면 `check_vault`의 "캔버스" 항목이 실패하는가 | 6-1절 캔버스 규칙 5, 12절 엣지 케이스 |
| D5 | 다시 그리면 "캔버스" 항목이 통과하고, 파일이 D2의 것과 같은가 | 6-1절 캔버스 규칙 5·6, 12절 엣지 케이스 |
| D6 | 옵시디언에서 가운데 방향 질문, 간 길(색)과 안 간 가지(색 없음), 멈춘 왜와 질문 노트, 왼쪽의 링크 카드(선 없음)가 보이는가 (눈으로 확인) | 6-1절 카드 규칙 |
