# check — 점검

이 스킬은 검사 스크립트를 실행하고 결과를 쉬운 말로 풀어 줍니다. 아무것도 고치지 않습니다.

- **먼저 읽을 곳:** `design.md` 11절(검사 스크립트, 스킬)
- **모드:** 없음 (3-1절의 세 모드 밖. 읽기만 함)
- **쓸 수 있는 곳:** 없음. 볼트, 스크립트, 설계 문서를 고치지 않고 커밋하지 않습니다.
- **쓰지 않는 것:** 고친 글 제안(내 말을 대신 쓰게 됨), 캔버스 열기(6-1절 캔버스 규칙 3)

## 1. 실행

저장소 맨 위에서 실행합니다.

```
python3 scripts/check_vault.py
```

- 종료 코드 0: 모두 통과. `[건너뜀]` 줄이 있으면 무엇을 왜 건너뛰었는지 한 줄씩 알립니다.
- 종료 코드 1: 실패가 하나 이상. 아래 2대로 설명합니다.

## 2. 설명

실패 줄은 `파일:줄 — 무엇이 틀렸나 (design.md 몇 절)` 모양입니다. 줄이 `HEAD 42`면 마지막 커밋의 42번째 줄입니다.

항목별로 묶어, 실패마다 세 가지를 쉬운 말로 말합니다.

1. **무엇이 틀렸나**: 파일과 줄, 지금 어떤 모양인지. 내 말이 걸린 실패면 그 줄을 원문 그대로 보여 줍니다.
2. **왜 규칙이 있나**: 스크립트가 적은 절을 읽고 한 문장으로.
3. **어디서 바로잡나**: 어느 회차 일인지만 알립니다. 고치는 방법을 대신 써 주지 않습니다.

| 실패 항목 | 바로잡는 곳 |
|---|---|
| 내 말, 받은편지함 | 바뀌거나 사라진 내 말은 마지막 커밋(`git show HEAD:경로`)에 원문이 있음. 되돌릴지는 내가 정함 |
| 안 간 가지, 사슬 제목, 사슬 마무리, 진행 상태(사슬) | 사슬 회차(`/chain`) |
| 밑줄과 생각, 진행 상태(받아 적기), 날짜 | 받아 적기 회차(`record`) |
| AI 구역, 순서, 링크 | 검토 회차(`/review`) 또는 내가 직접 말해서 |
| 구조, 파일 이름, 속성, 질문 노트 | 틀(`templates/`)과 6·7·11절을 보고 내가 정함. 파일 이름은 바꾸지 않는 것이 원칙이므로(11절) 먼저 묻습니다 |

마지막에 "실패가 있으면 커밋하지 않습니다(11절)"라고 한 줄로 알립니다.
